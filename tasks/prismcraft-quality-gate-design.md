# 任务书：模型无关质检层 + 自研模型接入方案设计

> 任务性质：**设计任务**（先出方案，不实施）

## 一、背景与决策依据

### 1.1 项目定位再确认
PrismCraft 的护城河不是"自研视觉算法"，而是**"AI 视频工作流编排平台"**——模型无关、本地优先、完整工作流。核心壁垒在工程化（DDD 六层 + 契约驱动 + 回归守卫 + 8824 测试全绿），而非算法层。

### 1.2 已确认的商业策略
**不投入成本自研视觉算法**，改为：
1. **留好接口**：保持/强化模型无关抽象，让"有自研模型的企业"（收购方）能低成本接入
2. **把质检/一致性做成模型无关的中间层**——这是接口的"语义"：不管用谁的模型生成，统一过一致性检测、穿帮检查、特征锚定。收购方看到的是"我们的模型接入后，能被你的工作流放大"
3. **证明接入成本极低**（目标：新模型 1 天接入）——这是给收购方看的价值证明

### 1.3 关键认知（设计时须牢记）
| 认知 | 含义 |
|---|---|
| 接口是必要条件，不是卖点 | 收购方买的是"省下的产品化时间"，不是"省下的 adapter 时间" |
| 接口的"语义"比"形式"值钱 | 质检层要让模型企业看到自己的模型在这里有放大场景 |
| 数据闭环是长期壁垒 | 用户生成数据 + 一致性判断确认/否决 → 可微调，越用越准 |
| 不做"算法崇拜" | 目标不是超越 Kling，是"跨提供商的一致性保证"（平台层差异化） |

## 二、设计目标
设计**模型无关的质检层（Quality Gate Layer）** + **自研模型接入规范**：
1. **跨提供商统一质检**：无论产出来自哪家（Kling/Seedance/自研模型），统一过质检管线（角色一致性、场景一致性、穿帮、色调/构图异常）
2. **能力可插拔**：质检器可插拔（规则引擎 + embedding 打分 + VLM 比对 + 未来自研模型），注册/配置接入，不改上层
3. **双时机**：生成前规划（P3.5 方向）+ 生成后检查（现有 consistency-check 方向）
4. **收购方视角接入文档**：明确"自研模型 1 天接入"路径

## 四、设计任务分解

### 任务 1：模型无关质检层架构设计
1. **分层归属**：放 `shared-logic/quality-gate/`（零依赖，与 director-rules 同级）还是 `modules/shot/` 子域扩展？给出推荐 + 理由（依赖方向、复用面、与现有 consistency-check 关系）
2. **核心接口草案**：`QualityGate` / `QualityChecker` / `QualityReport` 类型定义（Result 风格）
3. **质检器注册机制**：规则引擎 / embedding 打分 / VLM 比对 / 自研模型如何统一注册？参考 executor 注册表（`registerNodeExecutor`）与插件注册模式
4. **双时机接入点**：生成后（`checkVisualConsistency` 调用点升级）+ 生成前（P3.5 共享规则）
5. **阈值与反馈闭环**：per-provider/per-model 阈值可配置；用户"确认/否决"回流设计（本期只留数据接口，不训练）
6. **失败语义**：软提醒 or 硬阻断？遵循"失败即预期"哲学（降级链/透传兜底）

### 任务 2：自研模型接入规范（"1 天接入"承诺）
1. **最小接入面**：自研模型企业最少实现哪些接口？（对照 IVideoProvider + 声明式 JSON 插件找最短路径）
2. **《自研模型接入指南》目录结构**（面向收购方/技术负责人）
3. **接入示例**：mock 自研模型 provider + 1 个质检器的可运行示例，验证 1 天承诺
4. **能力声明升级**：现有能力映射是否足以表达"自研一致性模型"这类新能力？需要扩展什么？
5. **与插件系统关系**：走 code-plugin 还是声明式 JSON？边界在哪？

### 任务 3：收购方价值展示包（文档设计）
1. 《面向模型企业的接入价值文档》大纲：突出"模型接入后被工作流放大的场景"（一致性质检、批量生成、分镜编排、数据闭环）
2. demo 方案：录"新模型 1 天接入"视频的步骤/素材
3. 形式：markdown 大纲即可
